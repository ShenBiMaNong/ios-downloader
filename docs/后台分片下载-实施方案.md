# HLS 原生后台分片下载（background URLSession）实施方案

> M6.12 · 2026-11-14
> 目标：同时拿到「锁屏期间继续下载」和「自有 mp4 产物」，绕开 `.movpkg`。
> 状态：代码已落地；🔴 本机 Windows 无 Xcode / Flutter CLI，Swift 与 Dart 均未编译，需真机验证。

## 1. 结论先行

**这补的是「下分片不占亮屏时间」，不是「锁屏自动产出 mp4」。**

系统级后台只能覆盖「传输」这一阶段；ffmpeg `-c copy` 是 CPU/IO 密集操作，系统唤醒窗口
（要求尽快调 `completionHandler`）不够跑，因此分片下齐后作业停在 `ready`，等 App
回前台 / 冷启动时再合成。用户强杀 App（多任务界面划掉）时，系统取消该 session 的
全部传输且不再自动重启 —— 这一条与系统 `AVAssetDownloadTask` 链**完全一样**，
本方案并没有优于它。

优点：产物是 `Documents/Downloads/<标题>.mp4`，可进 `PlayerPage` 播放列表、可导出、
有文件大小与缩略图，不受 `.movpkg` 私有格式约束。

## 2. 数据流

```
页内角标 / 剪贴板导入
  → ConvertManager.nativeDownload()
  → [Dart 前台] Dio 拉 master/media 清单 → 解析分片 + AES-128 key
                → 写 Downloads/.native_<id>/playlist.m3u8
                → 组 NativeSegJob { jobId, workDir, parts[], headers }
  → MethodChannel submit() 一次性提交整个作业
  → [Swift] URLSessionConfiguration.background
                → 批量建全部 URLSessionDownloadTask 并 resume（不分批）
                → didFinishDownloadingTo 同步搬临时文件到 workDir/<name>
                → 更新 Documents/NativeSegJobs/<jobId>/state.json
  → 全部 task 结束 → state = ready | failed
  → EventChannel（前台实时）/ listJobs（冷启动、onResume 对账）
  → [Dart 前台] _finishNative() → ffmpeg -c copy → _finishMp4() → 入库
```

关键点：**Dart 不持有长任务**。`_runNative` 提交完立即返回，`_start` 释放 `_active`；
下载状态完全由原生侧磁盘 json 承担，EventChannel 只用于前台刷新。

## 3. 接口契约

### MethodChannel `video_downloader/native_seg`

| 方法 | 入参 | 返回 | 说明 |
|---|---|---|---|
| `submit` | `{jobId, workDir, playlistPath, parts:[{url,name}], headers:{k:v}}` | `Bool` | 建 task 成功即返回 true，**不代表下载完成**。已存在且非空的分片跳过（续传） |
| `cancel` | `{jobId}` | `Bool` | 取消该作业在途 task + 删状态记录；分片目录由 Dart 清 |
| `listJobs` | — | `[[String:Any]]` | 读全部 `state.json`，冷启动 / 回前台对账用 |
| `markRemuxed` | `{jobId}` | `Bool` | Dart 合成成功后删状态记录，避免重启被当成待合成 |

`parts` 同时包含 AES-128 密钥与分片；`name` 必须与 `playlist.m3u8` 里引用的文件名一致
（`key_N.bin` / `seg_N.ts`）。`headers` 传 `User-Agent` 与 `Referer`（此处用 media 清单
origin，不再用 Dio 全局写死的 B 站 Referer）。

### EventChannel `video_downloader/native_seg/events`

`{jobId, state, done, total, bytes, bytesTotal, bytesEstimated, error}`。`state`：`downloading | ready | failed`。
🔴 后台期间 Flutter 引擎可能根本没启动，事件会整段丢失，**不能作为唯一状态来源**。

字节字段（M6.13 起）：`bytes` = 已落盘分片字节 + 在途 task 已写字节；`bytesTotal` = 已落盘 +
在途已知 `Content-Length` + 未知分片按已知均值外推；`bytesEstimated` 表示总量含外推
（Dart 侧据此显示 `≈`）。`didWriteData` 只在 App 运行时被调用，所以**锁屏期间 `bytes` 不增长**
是系统行为，不是卡住；解锁回前台由 `listJobs()` 扫盘重建真实值。

### 原生侧持久化

`Documents/NativeSegJobs/<jobId>/state.json`：

| 字段 | 含义 |
|---|---|
| `parts` / `headers` | 作业定义；`taskDescription` 在后台重启后可能丢失，用它做 URL→name 查表兜底 |
| `state` | 作业状态 |
| `done` / `finished` / `failed` / `total` | 成功落盘数 / 已结束 task 数 / 失败数 / 总 part 数 |
| `bytes` | 已落盘分片字节合计（在途字节不落盘，回前台扫盘重建） |
| `workDir` | 分片目录（Dart 建的 `Documents/Downloads/.native_<id>`） |

`finished == total` 时定案：`failed > 0` → `failed`，否则 `ready`。读写用 `NSLock` 串行化。

### Dart 侧 API（`lib/services/native_bg_downloader.dart`）

`NativeBgDownloader.submit / cancel / listJobs / markRemuxed / events()`，
模型 `NativeSegJob` / `NativeSegPart` / `NativeJobStatus`。

## 4. 状态机（`ConvertTask.mode == 'native'`）

| stage | 触发 | UI 文案 | 下一步 |
|---|---|---|---|
| `''`（初始） | `nativeDownload()` | 准备中… | `_start` → `_runNative` |
| `downloading` | submit 成功 / 进度事件 / 对账 | 「3.2MB/s · 12.4MB/≈86MB · 剩余 2 分 10 秒 · 120/300」 | 系统继续下 |
| `ready` | 全部 task 完成 / 冷启动对账 | 待合成 MP4 | 回前台 `_finishNative()` |
| `remuxing` | `_finishNative` 开始 | 转封装中… | `_remux` → `_finishMp4` → `done` |
| `failed` | 任一分片失败 / 记录丢失 / 转封装异常 | 错误摘要 | 菜单「继续下载」重跑 `_run`（跳过已存在分片） |

M6.13 起所有下载链路共用一套进度文案，顺序固定
**速度 → 已下载/总大小 → 预估剩余时长 → 已下载分片/总分片**（`formatProgressLine()`）：

| 链路 | 速度 | 大小 | 剩余 | 分片 | 备注 |
|---|---|---|---|---|---|
| mp4 直链（Dio / Range 续传） | ✅ | ✅ 精确 | ✅ | — | 断点续传时 `bytesDone` 从 `.part` 长度起算 |
| 边播边缓存（http_cache_stream） | ✅ 落盘增量 | ✅ 已缓存 / ≈总量 | ✅ | — | 总量由「缓存文件长度 / progress」外推 → 标 ≈ |
| HLS 转 MP4（原生后台） | ✅ | ✅ 已落盘+在途 / ≈总量 | ✅ | ✅ 原生真实落盘片数 | 后台期间 `didWriteData` 不回调，数字停住属正常 |
| HLS 转 MP4（Dio 分片包） | ✅ | ✅ / ≈总量 | ✅ | ✅ 真实完成数（失败片不计） | 总量按已下片均值外推 |
| 系统 HLS 离线缓存（AVAssetDownloadTask） | ❌ | ❌ | ✅ | — | 系统只报媒体时长进度，末尾补百分比 |

字段缺失自动跳过；一个量化字段都没有时不显示空行（回落到「准备中…」）。

完成态走既有 `_finishMp4`：写 `<id>.json` 元数据、删工作目录与 `.convert.json`、
产物以 `kind='mp4'` 进资源库 / PlayerPage。

## 5. Apple 硬约束与本实现的应对

| 约束 | mechanism | 约束强度 | 本实现 / cost |
|---|---|---|---|
| 必须用 `URLSessionDownloadTask`，data task 不支持后台 | 系统只代跑 download/upload task | 🔴 硬 | `NativeSegmentBridge` 全部用 `downloadTask(with:)` |
| `didFinishDownloadingTo` 返回前必须搬走临时文件 | 临时文件只在 delegate 方法作用域内有效 | 🔴 硬 | 回调里同步 `moveItem` 到 `workDir/<name>`；并校验 HTTP 2xx，避免把 403 错误页当 `.ts` 落盘 |
| 大量小 task 被节流，且「每次唤醒延迟递增」 | 官方明确建议改成 fewer/larger transfers | 🔴 硬 | **一次性提交全部 task**，绝不沿用 `_downloadSegments` 的「批 4 → 下完再提交下一批」（:509） |
| 用户强杀 App → 取消全部后台传输、不再自动重启 | 系统策略 | 🔴 硬 | 无法规避；与 `HlsBridge` 同级。靠 `state.json` + 已落盘分片做续传 |
| 后台发起的传输强制按 `isDiscretionary` 处理 | 系统调度 | 🟡 | 前台 `submit` 时 `isDiscretionary=false` 立即开始；后台补提交仍会择机 |
| 重定向始终跟随，`willPerformHTTPRedirection` 不调用 | 后台 session 限制 | 🔴 | 无法重写 header；带签名/CDN 302 的源更容易失败，见 §7 |
| 系统唤醒窗口短，须尽快调 `completionHandler` | `urlSessionDidFinishEvents` 后可能立即挂起 | 🔴 | 合成一律放前台；`handleEventsForBackgroundURLSession` 暂存 handler，`urlSessionDidFinishEvents` 主线程调用 |
| 不需要 `UIBackgroundModes` | background session 由系统托管 | ✅ | `Info.plist` 未改；`BGTaskScheduler` 才需要声明 `fetch`/`processing` |

## 7. 已知限制（未在本轮修复）

- 🔴 **fMP4 / CMAF**：`_parsePlaylist` 一律命名 `seg_N.ts`（`m3u8_convert.dart:714`），
  `_writeLocalPlaylist` 跳过 `#EXT-X-MAP`（:805）；这类源转封装必失败。三条自下载链共有。
- 🔴 **DRM / 非 AES-128**：只认 `METHOD=AES-128`，其它直接抛异常。FairPlay 源只能走系统链。
- 🔴 **清单与分片的鉴权时效**：后台任务可能被系统推迟，带签名/短时效 token 的分片会 403；
  本实现会把 403 标成失败并保留已下分片，可点「继续下载」重试（但清单会重新拉）。
- 🔴 **iCloud 备份**：`Documents/Downloads/.native_*` 与 `NativeSegJobs` 未设
  `isExcludedFromBackup`，会计入备份且不会自动清理，容量需自己管。
- 🟡 **进度精度**：已改为字节口径（M6.13）。但 `bytesTotal` 依赖各分片的 `Content-Length`，
  清单不带大小时按已知均值外推（标 ≈）；`didWriteData` 在锁屏期间不回调，所以后台阶段
  `bytes` 原地不动，解锁回前台一次性跳到真实值——这是 Apple 的后台 session 语义，不是丢进度。
- 🟡 **并发合成**：多个 ready 作业回前台会并行跑 ffmpeg，未做串行队列。
- 🟡 README「已知限制」第一条仍写「HLS(m3u8) 暂不支持下载」，与 MVP-2/3/M6.12 矛盾，
  按约定未擅改，需确认后修订。

   贴回完整编译输出；有 error 先只修第一个。
2. `flutter analyze`（或 CI）验证 Dart 改动；贴回输出。
3. 真机装包 → 网页嗅探到 m3u8 → 点「后台下载并转 MP4」→ 确认资源库出现
   「3.2MB/s · 12.4MB/≈86MB · 剩余 2 分 10 秒 · 120/300」这类进度条目。
4. 下载中锁屏 3 分钟 → 解锁回 App → 确认字节数继续增长（证明系统代跑生效）。
   M6.13 起看的是字节数：锁屏期间 `didWriteData` 不被调用，数字**原地不动是预期的**；
   解锁回前台应一次性跳到真实值（扫盘 + 在途字节），且不会出现虚假的高速度（首帧只重建基线）。
5. 全部下完 → 回前台 → 确认自动变成 `kind='mp4'`，有大小/缩略图，可进 PlayerPage 连播。
6. 冷启动验证：下载到一半 **杀进程**（不是多任务界面划掉，而是 Xcode Stop / 系统回收）
   → 重开 App → 确认 `listJobs()` 对账后条目恢复进度并继续。
7. 强杀验证：多任务界面划掉 App → 重开 → 确认作业停在 `failed/已暂停`，可点「继续下载」续传。
8. 🔴 **场景回调落点**：本工程启用了 `UIApplicationSceneManifest` + `SceneDelegate`。
   本实现假设 background session 事件仍由
   `AppDelegate.application(_:handleEventsForBackgroundURLSession:completionHandler:)` 交付。
   若步骤 4/6 不生效，优先加日志确认该回调是否到达；若不到，需改由 Scene 侧接管。
9. 非 B 站源验证：确认 `Referer` 用 media origin 后分片不再 403；仍 403 则需把来源页
   `document.referrer` / 页面 URL 经 `VideoInfo` 传进来（当前 `VideoInfo` 只有 `frameUrl`）。
