# 视频嗅探「展现方式」体验调研报告

> 调研时间：2026-11 ｜ 范围：内置浏览器嗅探链路 `assets/sniffer.js` → JS Channel → `lib/pages/browser_page.dart` 浮标与弹层
> 现状结论以本仓库代码为第一证据（附文件:行号）；外部产品结论附官网链接，无法逐条核验处已标注「未能核验」。

---

## 1. 结论速览（TL;DR）

1. **有，而且提升空间很大**：当前把「嗅探到的视频」展现为一屏裸 URL 列表，用户只能靠看字符串猜内容；业界成熟产品（IDM 视频面板、浏览器下载扩展、Via 等手机浏览器）早已进化成「**非阻断浮标 + 视频卡片列表（缩略图/标题/清晰度/大小/时长）**」。
2. **主要成本不高**：已按用户确认的方向落地「页面内直接标记」（`video_marker.js`：描边 + 角标 + 页内操作卡，HLS 卡提供 m3u8/转 MP4 双下载），约半天改动、零新依赖；「信息增强」（缩略图/标题/时长/大小）与「交互增强」（分组/批量/噪点过滤）仍可后续叠加。
3. **顺手修两个噪声 bug**：当前把 `.ts` 分片也当独立视频上报（HLS 页面会刷几十条分片 URL）；且同一视频的不同清晰度 URL 会各占一行，让「发现 N 个视频」虚高。
4. **建议分两步走**：第一步信息增强（推荐先做），第二步交互增强（清晰度选择/批量下载/噪点过滤，按真机反馈再加）。

## 2. 现状逐条拆解（本仓库代码）

### 2.1 现有链路

```
sniffer.js（注入页面）
  ├─ ① 扫描 <video>/<source>    ② MutationObserver
  ├─ ③ 钩 fetch / XHR           ④ 兜底轮询
  └─ 命中 /\.(mp4|m3u8|mov|webm|ts)([?#]|$)/ → postMessage({url, frame, page})
                                          ↓
browser_page.dart  addJavaScriptChannel('videoFound')   [browser_page.dart:50]
  └─ VideoInfo(url, frameUrl, pageTitle) 按 URL 去重插入 _found [browser_page.dart:105-106]
                                          ↓
底部浮标「发现 N 个视频」[browser_page.dart:223-255]
  └─ 底部弹层：每行 = 图标 + 裸 URL + kind + 下载按钮 [browser_page.dart:257-329]
```

### 2.2 痛点清单

| # | 痛点 | 代码证据 | 用户感受 |
|---|---|---|---|
| P1 | **列表项标题就是裸 URL** | `title: Text(v.url …)` [browser_page.dart:282] | 满屏 `https://…/xxx/abc_1080p.mp4?sign=…`，看不出哪个是当前视频 |
| P2 | **信息量只有 kind** | 副标题仅 `v.kind.toUpperCase()` [browser_page.dart:283-286] | 没有时长/分辨率/大小/缩略图，无法判断「值不值得下」 |
| P3 | **同一视频多清晰度 → 多行重复** | 按 URL 字符串去重 [browser_page.dart:105]、sniffer.js:12 | 一个视频常出 3–5 行几乎相同的行，「发现 N 个」虚高 |
| P4 | **噪声无过滤、无法忽略** | 命中即报，只按扩展名 [sniffer.js:6-14]；列表无「忽略」操作 | 广告/埋点/预览小样混入；`.ts` 分片也整批上报 |
| P5 | **无批量操作** | 每行一个下载按钮 [browser_page.dart:287-319] | 多视频页面要一条条点 |
| P6 | **发现无即时反馈** | 只有浮标计数变化 [browser_page.dart:240-245] | 用户在看视频时几乎无感知，回头才看到计数 |

> 补充：`MAX = 30` [sniffer.js:7] 只在「满了」时静默丢弃新视频，用户无感知；且 `frame/page` 字段已回传但**展示层完全没用上**（页面标题、来源页面信息被丢弃）。

## 3. 业界做法（调研）

### 3.1 桌面：下载管理器 + 浏览器扩展

- **Internet Download Manager（IDM）**：官方明确宣传「IDM video download panel」——浏览网页时自动浮出视频下载面板，以及「Download All links」一键抓取页面全部可下载媒体。
  [IDM 官网首页](https://www.internetdownloadmanager.com/) ｜ [IDM 功能页](https://www.internetdownloadmanager.com/features2.html)
- **Video Download Helper（火狐/Chrome 扩展）**：工具栏图标角标计数 → 点击弹出列表，每项为**文件名 + 格式 + 大小**，可选清晰度/格式后下载。
  [官网](https://www.downloadhelper.net/)（本次调研官网抓取失败，行为描述为使用经验，**未能核验**）
- 共性：**非阻断浮标**（角标/胶囊）＋**可展开面板**，面板内信息对人类可读（名称/格式/清晰度/大小），支持一键全部。

### 3.2 移动端：手机浏览器内置嗅探

- **Via 浏览器（Android）**：检测到视频后页面角落浮出下载图标 → 点开是视频列表，按「标题/清晰度/大小」展示，可**选清晰度**下载；是安卓轻量浏览器「视频嗅探」的典型体验。
  [Via 官网](https://viayoo.com/zh-cn/)（官网未展开描述该细节，**未能逐条核验**，为社区共识用法）
- **iOS 下载器类（Documents by Readdle 等）**：内置浏览器内检测到可下载媒体 → 页面顶部/角落出现「下载」胶囊，点击进入内嵌下载页，下载完成直接落本地文件库。
  [Documents](https://readdle.com/documents)（官网本次抓取跳转失败，**未能核验**）
- 共性：**小浮标提示 + 大面板**，浮标负责「有货了」，面板负责「是什么、怎么下」。

### 3.3 技术参考：浏览器 DevTools Network 面板

按 MIME 类型/域名分组、可过滤（仅视频/大文件）、显示大小与耗时——「分组 + 过滤」是信息展示的标准做法，可直接借鉴到嗅探列表（P3/P4 的对症药）。

### 3.4 共性提炼（可直接抄的四个模式）

1. **非阻断浮标**：只提示「有 N 个可下载视频」，绝不打断浏览。
2. **列表项 = 视频卡片**：缩略图 + 人类可读标题 + 格式/清晰度/大小/时长 chips，而不是 URL。
3. **支持清晰度/格式选择**（HLS master 清单天然带清晰度，mp4 链接可解析分辨率 token）。
4. **批量与忽略**：「全部下载/多选」+ 单条忽略（噪点治理）。

## 4. 推荐方案

### 4.1 第一步：信息增强（低成本，先做）

**A. `sniffer.js` 增补元数据**（纯前端，零新依赖）

- 从 `<video>` 元素取：`duration`、`videoWidth × videoHeight`（`loadedmetadata` 后尽力取，MSE/blob 流可能为 NaN，置空）、`poster`；
- 从页面取标题/缩略图：`og:title` → `document.title`；`og:image` → `video.poster` → 页面首图；
- 对 m3u8 **master 清单**尽力解析 `#EXT-X-STREAM-INF` 的 `RESOLUTION/BANDWIDTH` 得到清晰度档位（跨域受限时降级为空，由 Dart 侧兜底）；
- 顺带修噪声：**`.ts` 分片不再单独上报**（HLS 走 m3u8 整包下载，分片 URL 无意义）；同一 `<video>` 元素的多 URL 归一组。

**B. `VideoInfo` 扩字段** [lib/models/video_info.dart]

- 新增：`title`（og:title 优先）、`thumbnail`、`duration`、`width×height`、`sizeBytes`（异步探测后回填）、`groupKey`（所属 video 元素/页面）。

**C. Dart 侧异步大小探测**（best-effort，3–5s 超时 + 按 URL 缓存）

- mp4：`Dio` 发 `Range: bytes=0-0`（或 HEAD），读 `Content-Range`/`Content-Length`；
- m3u8：无法直接得大小 → 用「variant 带宽 × 时长」估算，或干脆显示「HLS 流」；
- 部分站点防盗链（Referer 校验）或拒绝 HEAD → 留空显示「大小未知」，不影响主流程。

**D. 弹层卡片化**（替换 [browser_page.dart:257-329] 的裸 URL 列表）

```
┌─────────────────────────────────────────┐
│ 发现视频（3）                    [全部下载]│
├─────────────────────────────────────────┤
│ ┌────┐ 片头标题（og:title / 页面标题）      │
│ │缩略图│ MP4 · 1080p · 03:20 · 约145 MB   │
│ └────┘  [忽略]                    [下载]   │
│ ┌────┐ 第二个视频标题 …                    │
│ │缩略图│ HLS · 720p · 12:40 · 流媒体        │
│ └────┘  [忽略]              [缓存] [转MP4]  │
└─────────────────────────────────────────┘
```

- 每卡片：缩略图（`Image.network(headers:…)`，失败降级为图标）+ 标题 + 元数据 chips + 单卡下载；
- 浮标同步升级：显示首条缩略图小圆 + 「发现 N 个视频」，点击进弹层。

### 4.2 已确认方向：页面内直接标记（方案A，2026-11 用户确认）

> 用户拍板：**不弹层**，嗅探结果直接标在网页里的视频元素上（「视频部分显示特定样式」）。

**已实现（`assets/video_marker.js` + `browser_page.dart`）：**

- 每个命中 `\.(mp4|m3u8|mov|webm)` 的 `<video>`：加**蓝色虚线描边** + 右上角**胶囊角标**（蓝=直链，紫=HLS；角标显示分辨率或 `HLS`，HLS 可带时长）；
- 点角标 → 视频旁展开**页内操作卡**（非弹层）：
  - 直链：`下载视频` / `复制链接` / `忽略此条`；
  - **HLS：`缓存 m3u8（离线播放）` + `转 MP4` 两种下载方式**（用户要求）/ `复制链接` / `忽略此条`；
- 操作经 `videoAction` JS 通道回传 Dart，复用 `DownloadManager` / `HlsManager` / `ConvertManager`；
- 标记跟随滚动（scroll/resize/1s 轮询），全屏播放时自动隐藏；`.ts` 分片不单独标记；「忽略」即时移除角标与描边；
- 菜单新增「视频标记：开/关」（持久化，默认开）；fetch 抓到但无可见 `<video>` 的流（blob: 等）仍由底部小胶囊兜底。

**取舍：** 不遮挡控制条（角标贴右上角外沿）；跨域 iframe 内的播放器标记不到（沿用 WKWebView 主框架注入限制）；元素级 `transform` 容器内 fixed 角标位置可能有偏差（罕见，接受）。

### 4.3 第二步：交互增强（按真机反馈再加）

1. **分组折叠**：按 `groupKey`（页面/video 元素）分组，组内多清晰度折叠选择（对应 P3）；
2. **多选批量下载**：复用现有 `DownloadManager` 队列 [lib/services/download_manager.dart:100] 与 `HlsManager`，加「全选/全部下载」；
3. **噪点过滤**：复用 `assets/adblock.js` 的广告域名表过滤候选；支持长按「忽略此条/此域名」；
4. **嗅探历史**：每页面最近嗅探结果留存（配合 MVP-5 历史记录），切页不丢。

### 4.4 明确不做/维持降级

- `blob:`(MSE) 仍无直链，维持「不支持离线下载」提示（沿用现有结论）；
- 不做「原生网络层拦截」——WKWebView 无法拦截 http/https（沿用技术调研报告 §3.1 结论）；
- 缩略图对强 Referer 校验的 CDN 可能加载失败，允许降级为图标即可，不为此上服务端代理。

## 7. 实施记录：识别类型扩充（2026-11）

按用户要求「尽可能识别多的视频类型」完成一轮增强（`assets/sniffer.js` + `assets/video_marker.js` + `lib/models/video_info.dart` + `lib/pages/browser_page.dart`）：

**新增可识别类型：**

| 类别 | 新增 | 表现 |
|---|---|---|
| 直链容器 | mkv / flv / f4v / m4v / ts / m2ts / mts / mpg / avi / wmv / asf / 3gp / ogv / rm / rmvb | 角标按真实格式显示（MKV/FLV/TS…），下载走通用 HTTP 直链 |
| 流媒体清单 | DASH `.mpd` | 单独分类，卡内明示「暂不支持离线下载」 |
| 无扩展名签名 URL | 任意 URL，靠**响应 Content-Type**（`video/*`、x-mpegurl、dash+xml、mp2t）兜底 | fetch/XHR 钩子读响应头，识别后入列表/可出角标 |
| MSE/blob 播放 | `<video>.src = blob:` | 用嗅探器（`window.__vdlSniff`）最近捕获的 m3u8/直链兜底出角标；未捕获则显示灰色「流」角标并说明原因 |
| `<source>` 子元素 | video 无 src 时读子元素，`type` MIME 命中即认 | 角标与列表均可命中 |
| iframe 内播放器 | 同源 iframe（脚本自扩散 `propagate`） | iframe 内视频也能出角标/上报 |
| **懒加载影视站（点击播放后才请求媒体）** | 点击监听（capture 阶段）+ `<video>/<source>` 的 `src` 属性变化观察（attributeFilter） | 点击后毫秒级出角标/入列表，不再等 1–2s 轮询；fetch/XHR 钩子本就在请求瞬间捕获 |
| **静态脚本解析（点击前识别）** | 扫描 `<script>` 文本里的视频地址（含 JSON 转义斜杠 `\/`），如 `player_x={"url":"…m3u8"}`、`window.__INITIAL_STATE__` | 很多影视站把真实地址嵌在页面配置里，**未点击也能识别**入列表 |
| **Performance API 资源时间线** | `performance.getEntriesByType('resource')` 轮询（增量游标），被动收集所有已请求资源 | 兜底「站点缓存原始 fetch 引用绕过钩子」的漏网；注入前已发生的请求也能补到 |
| **iOS WKUserScript 早期全帧注入（原生桥）** | `video_downloader/sniffer` 通道 → 把 sniff 脚本注册为 `atDocumentStart + forMainFrameOnly:false` 的 user script | 先于页面脚本挂钩 fetch/XHR（防引用缓存绕过）；**跨域 iframe 播放器帧也注入**（WKWebView 全帧注入是文档化行为）；每次文档加载（含动态创建的 iframe）都会执行 |

**顺带治理噪声：** `.ts`/`.m4s` 分片与字幕（vtt/srt/ttml…）不再作为独立视频上报（元素直链除外）；MIME 兜底路径同样受此限制，避免 HLS 分片刷屏（此前 P4 痛点）。

**已知边界（沿用/平台限制）：**
- 跨域 iframe 无法注入与读取（浏览器安全限制，iOS/Android 均不可绕过）；
- MSE 无直链本质不可离线下载，兜底 URL 为「最近捕获」启发式，多视频同页时可能与当前视频错位；
- blob: 兜底 URL 依赖 sniffer 先行注入（页面加载即注入，正常无差）。

> 验证：`node --check` 语法通过；Node 冒烟测试 10/10 通过（扩展名识别、MIME 兜底、分片噪声过滤、注册表、iframe 扩散守卫、marker 安装）。Dart 侧因本机无 Flutter SDK 未跑 `flutter test`（`test/video_info_test.dart` 已按新类型扩充用例）。

## 6. 结论

- 嗅探视频**有更友好的展现方式，且业界已有成熟范式**：浮标提示 → 卡片列表（缩略图/标题/清晰度/大小/时长）→ 单卡或批量下载。
- 已按用户确认的「方案A」落地：**可下载视频直接标在网页元素上**（描边 + 角标 + 页内操作卡，HLS 卡提供 m3u8/转 MP4 双下载），替代 Flutter 弹层；「信息增强」（缩略图/标题/时长/大小）与「交互增强」（分组/批量/噪点过滤）作为后续叠加项。
